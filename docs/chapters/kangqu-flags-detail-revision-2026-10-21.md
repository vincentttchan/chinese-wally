# 持旗群像：面貌與細節修訂

2026-10-21。使用者確認整組摹繪底稿理想，但指出放進畫作後面貌及細節缺失。

## 原因

上一版以 1254×1254 的九格素材製作動畫，每組人物只占約 300 多像素寬。生成時已簡化了鬍鬚、眼鼻及五瓣花紋，再規整成 430×470。執行時又使用固定 430×470 的 canvas 及相同尺寸的離屏畫布；高像素密度螢幕會再放大這個小畫布。這同時是素材細節和繪製解析度問題，單純放大 PNG 或銳化不能補回。

## 修訂

- 已確認的 `kangqu-flags-v1/group-master.png` 保留不動，動畫起手與收勢直接使用該底稿。
- 左旗起動、右旗回應各以一張三格橫排素材製作，兩張均以同一底稿為參考，強調眼眉、鬍鬚、衣上小花、繩結與龍紋。原始輸出各為 2078×757，單組有約 700 像素寬的素材空間。
- 每張只取前兩組完整人物；最右格靠近邊緣的畫格未採用。四個動作姿態與精確底稿構成九格播放時序，重用姿態作回應與收勢，沒有把小圖放大當作新增細節。
- 新執行素材規整到 1311×1366，以共同來源高度尺度及整組鞋子錨點平移對位。不拆頭、手、人物或旗面，不變形原畫。
- 原畫裁切範圍略擴為 `[3300,1270,3770,1760]`，留出旗面動作邊距；背景仍是同一張固定底圖。
- 播放畫布依目前顯示尺度及 devicePixelRatio 配置像素；圖像直接繪製到該解析度，不再經過原畫大小的中間畫布。保留影像的高品質縮放。
- 樣段標示「細節修訂」，沿用同一路由 `#kangqu-flags-preview`。預覽視角的桌面錨點固定，避免首次尺寸回報的時序令重新載入後構圖不同。

## 素材記錄

- `output/art-direction/kangqu-flags-v2-detail/generation.json`：內建 image_gen 的完整提示詞、原始輸出位置與選用規則。
- 同目錄 `normalize-animation.py`：整組規整與對位，未替換或刪除原 v1 素材。
- `public/art/animations/kangqu-flags-v2-detail/`：實際執行的原畫裁切、固定背景、畫格及配準記錄。
- 代表畫面：`preview-master-rest.png`、`preview-response.png`、`preview-settled.png`、`preview-normal-speed.png`。

## 實際檢視

本機 IAB、約 806×853 視窗：正常及慢速播放、自然結束回原畫、重播與略過。慢速第一、五、八格已保存；正常播放檢視第四格。新版可辨認鬍鬚、眼鼻及細小花紋；起手與收勢為精確底稿。背景沿用固定底圖。

DOM 讀取得到顯示寬約 423 CSS px、畫布 847×883、來源圖寬 1311；確認此視角按 2 倍螢幕像素繪製。重新載入後的播放沒有新增 error / warn，也沒有框架錯誤覆蓋。`npm run build` 完成；原有大型 bundle 提示仍在。沒有新增或執行自動測試。

## 限制

動作姿態仍是生成變體，面貌及花紋不會逐像素等同底稿；精確底稿只保證起手及收勢。未另做手機、其他 DPR 或減少動態偏好檢視。尚待使用者確認實際細節與動作效果。此輪只修訂獨立樣段，未接回正式章節或推送 GitHub。
